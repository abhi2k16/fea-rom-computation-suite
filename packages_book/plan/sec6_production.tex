\section{Production plan}\label{sec:production}

\subsection{Folder layout}
\begin{verbatim}
packages_book/
  README.md              what this folder is, how to build
  plan/                  this document (main, macros, sec*.tex, refs.bib)
  book/                  created when writing starts
    main.tex  macros.tex  refs.bib
    chapters/ch01.tex ... ch14.tex  appA.tex
    figures/  tables/  listings/    generated, never edited by hand
    scripts/                        one script per figure or table
\end{verbatim}
The book reuses the conventions of \code{paper/}: a shared macro file, numbers generated into macros, figures built by scripts, and \texttt{latexmk} for the build.

\subsection{Order of work}
\begin{enumerate}
\item \textbf{Set-up.} Book skeleton, macro file, numbers pipeline, bibliography, the nine items of \Cref{tab:todo}.
\item \textbf{Part II core first} (Chapters~\ref{ch:elem}, \ref{ch:nonlin}, \ref{ch:batch}, \ref{ch:contact}), because it holds the most measured material and the contact chapter is the book's distinctive contribution.
\item \textbf{Part I and Chapter~\ref{ch:dyn}}, written after the code it describes is fixed.
\item \textbf{Part III} in the order of \Cref{fig:deps}.
\item \textbf{Part IV and the appendix}, then index, notation list and the anchor-to-path table.
\end{enumerate}
Each chapter is reviewed against the repository at its release tag, and every listing is executed in the build.

\subsection{Risks}
\begin{itemize}
\item \textbf{Code drift.} The packages still change. Mitigation: pin a tag per edition and cite by importable name.
\item \textbf{Unmeasured claims.} The new gallery scripts (\code{fea_09}, \code{fea_10}, \code{rom_07}) were run only in the development sandbox; they need a run on the author's machine before their numbers enter the book.
\item \textbf{Scope creep.} The package has many modules that the plan leaves out (topology optimisation, adaptivity, iterative solvers, harmonic-balance hyper-reduction, friction models). They appear only as pointers.
\item \textbf{Length.} 440 pages is a ceiling; Chapters~\ref{ch:elem} and~\ref{ch:nonlin} are the first to shorten.
\end{itemize}

\subsection{Decisions taken}
The five open questions of draft~1 were answered by the author.
\begin{enumerate}
\item \textbf{Companion to a pinned release.} The book is a companion to a tagged release of the repository; it is not a stand-alone text. Every listing, number and code anchor refers to that release. The current versions are \fea{} 1.0.1 and \rom{} 0.2.0; the tag itself is to be created by the author when the text is frozen, and all results quoted in the book are re-run at that tag.
\item \textbf{FD-PINN reproduction stays in Chapter~\ref{ch:verif}} as a verification case study, presented as a check of the reproduction procedure and not as a neural-network method.
\item \textbf{One paragraph on the neural-operator code} in Chapter~\ref{ch:nonint}; no neural-network chapter.
\item \textbf{Format.} A4, class \texttt{book}, in the layout of \code{paper/macros.tex}.
\item \textbf{Appendix~A (differentiable assembly) stays.}
\end{enumerate}

\subsection{Blueprint review: items adopted}\label{sec:blueprint}
An outside blueprint for a longer, from-scratch textbook (24 chapters, Parts on FEM theory, MOR theory and integrated workflows) was compared with this plan. Its Parts on linear algebra, continuum mechanics, weak forms and element derivations are out of scope for a companion book (decision~1 above), as are its 24-chapter structure, the 12-month schedule, a printed API reference and extended GPU material. The following items are adopted. They were applied in one editing pass after Chapters~\ref{ch:nonint} and~\ref{ch:hyper} were written, so that no chapter was revised twice; status is as below.
\begin{enumerate}
\item \textbf{Learning objectives.} Three to four ``after this chapter the reader can \dots'' items added to the chapter box of every chapter. \emph{Status: done for Chapters~\ref{ch:arch} to~\ref{ch:hyper}.}
\item \textbf{Three exercise types.} Each chapter's exercises contain at least one derivation, one implementation and one critical-interpretation exercise, tagged as such. \emph{Status: done for Chapters~\ref{ch:arch} to~\ref{ch:hyper}; the exercises added to Chapters~\ref{ch:arch} to~\ref{ch:cms} to complete the set are new and have not been worked through by the author.}
\item \textbf{``How to read the verification sections''.} A short front-matter page defining unit test, verification and validation (no result in this book is validation against experiments; a passing test is not proof of general correctness) and listing what each reported number states: model and loading, solver settings, reference value, error definition, release and machine. A back-matter appendix gives the convergence-study template and the tolerances used. \emph{Status: done (reading-guide page and Appendix~B of the book); the tolerance table lists the settings of the listings and defaults named there, not every tolerance in the book.}
\item \textbf{Fuller ROM reporting} in Chapters~\ref{ch:pod}, \ref{ch:freq} and~\ref{ch:verif}: offline, online and reconstruction time reported separately; each speed-up states whether it includes preprocessing; a local quantity (a reaction or peak stress) reported next to the global relative error. \emph{Status: partly in Chapter~\ref{ch:pod} (offline and online separated, dense baseline stated); Chapters~\ref{ch:pod}, \ref{ch:freq}, \ref{ch:nonint} and~\ref{ch:hyper} now report offline, online and lift cost separately, break-even including the offline cost, and a local quantity next to the global error (Appendix~B of the book states the convention); no reaction or peak stress was computed, and Chapters~\ref{ch:bt} and~\ref{ch:cms} do not apply the convention.}
\item \textbf{Benchmark discrepancy.} The README and user guide give 221.8$\times$ (1653.23~ms against 7.45~ms, 500-point sweep, maximum error $1.51\times10^{-3}$); a figure of 254$\times$ from an earlier manuscript does not occur anywhere in the repository. Chapter~\ref{ch:verif} quotes its own regenerated ratio against the tagged release and gives 254$\times$ only with its own conditions; the two are never merged. \emph{Status: open. A search of the repository and the paper finds 254$\times$ nowhere; the paper's own run gives $361\times$ (author machine, commit 33cde35) and the README $221.8\times$. Chapter~\ref{ch:verif} will report its own regenerated ratio next to those two, each with its source. The repository now has its first tag, \code{release-fea1.0.1-rom0.2.0} (commit f87baf3); the book is pinned to it.}
\item \textbf{One complete integrated run} (full-order model, snapshots, reduced model, held-out check, reconstruction) in Chapter~\ref{ch:verif}. \emph{Status: done (Section~\ref{sec:vf-pipeline}, \code{ch14_pipeline.py}).}
\item \textbf{Maturity labels.} A stable / experimental / not-covered column in each chapter's code-map table. \emph{Status: done in an operational form: the column is headed ``Script calls'' and says whether the chapter's script calls the code of the row by name (yes, part, no); ``stable'' and ``experimental'' were not assigned, because that is a judgement of the author, and the neural models are described as experimental in the text of Chapter~\ref{ch:nonint}. The column is a lower bound (code reached through another routine counts as no) and should be reviewed by the author.}
\item \textbf{Glossary and notation appendix}, and a table mapping each chapter to its script and to the package tests that cover it. \emph{Status: done (Appendices~C and~D of the book); the test list is chosen by file name and is a pointer, not a coverage claim.}
\end{enumerate}
\subsection{Presentation upgrade: abbreviations, algorithms, figures}\label{sec:presentation}
Taken from the conventions of the companion paper (\code{paper/arxiv_submission}), approved by the author, applied after the blueprint pass and before Chapter~\ref{ch:verif} is written, so that Chapter~\ref{ch:verif} is written in the new style. Status is updated here.
\begin{enumerate}
\item \textbf{Abbreviations.} A front-matter table of about 55 entries in the paper's four-column layout (the paper's 40 plus book terms such as BDF2, CB, BT, KKT, LCP, NMF, PSD, RID, HBM, SPD, SVD, FOM); every abbreviation is spelled out at first use in each chapter; Appendix~C keeps notation and concept entries without duplicating the table. \emph{Status: table done (45 entries, front matter); the first-use check in each chapter is part of the rollout.}
\item \textbf{Algorithm style.} Numbered pseudocode (Require, State, For, If, Comment lines) inside the existing \code{algbox}, followed by book-level lines: inputs and outputs, cost per call, how it fails (the signal the code gives), code anchor, and the table or section that verifies it. The nine existing boxes are converted (Newmark, Newton, active set, offline--online, systems-and-control choice, greedy frequency, Craig--Bampton, hybrid nonlinear ROM, hyper-reduced contact ROM). About twenty are added: global assembly and backend dispatch (Ch.~1); grading by bisection (2); explicit central differences and harmonic sweep (4); arc length, J2 radial return and Koiter--Newton (5); chunked batched assembly (6); BDF2 contact step (7); POD from snapshots (8); square-root balanced truncation, Arnoldi and SOAR (9); certified bound and PSD response (10); interface reduction and component POD (11); Loewner, operator inference and harmonic-balance continuation (12); ECSW training, NMF dual basis, greedy contact and partition condensation (13); the integrated pipeline (14). \emph{Status: environments \code{pseudo} and \code{algdet} added to \code{macros.tex}; pilot done in Chapter~\ref{ch:pod} (2 algorithms) and Chapter~\ref{ch:hyper} (5 algorithms); batch 1 done: Chapters 1--7 have 13 algorithm boxes (3 converted: Newmark, Newton, active set; 10 added), Koiter--Newton deliberately omitted because the book does not verify it; batch 2 done: Chapters 9--12 have 13 algorithm boxes (4 converted: Ch.~9 choice, Ch.~10 greedy, Ch.~11 Craig--Bampton, Ch.~12 hybrid ROM; 9 added: square-root balanced truncation, Arnoldi, SOAR, certified bound, PSD response, interface reduction, component POD, Loewner, operator inference, harmonic-balance continuation); Chapter 14: Sections 14.1 to 14.3 written; eight reproduction figures redrawn by \code{ch14_assets.py} from the saved outputs of the study folders (not re-run: the sandbox has 2 cores, 3 GB and about 3 minutes per command; \code{--rerun --jobs N} re-runs a study in a scratch copy and was not executed in full here); Section 14.4 written (integrated pipeline run by \code{ch14_pipeline.py}: two meshes, held-out parameters and loads, reported by Appendix~B; the three speed-up figures explained); Section 14.5 remains.}
\item \textbf{Concept figures} (about 35 new TikZ diagrams, all three tiers, in the paper's colour code: FE package blue, ROM package violet, error measure green, plain-array interface grey, validation-only feedback dashed). Tier~1, essential: FESystem pipeline and FE/ROM boundary (1); snap-through curve comparing load control, displacement control and arc length (5); loop against batched data flow (6); gap--force complementarity with the active-set iteration (7); offline--online timeline (8); map of reduction methods (9); greedy loop (10); substructure with interface and Craig--Bampton basis columns (11); ICE against surrogate pipeline (12); ECSW element selection, dual-basis contact problem and linear/nonlinear partition (13); end-to-end workflow (14). Tier~2, helpful: weak form to matrix, shear-locking mechanism, time-scheme stability map, solver-choice flowchart, Loewner pipeline, NNM backbone sketch, operator-inference structure, hybrid reduced-domain sketch and similar. Tier~3, optional: mesh-interface sketches, a ``which ROM when'' decision chart, a chapter-dependency map, a verification pyramid. \emph{Status: TikZ styles and \code{\textbackslash tikzfigure} added; pilot done: 3 figures in Chapter~\ref{ch:pod} (pipeline, two projections, break-even) and 5 in Chapter~\ref{ch:hyper} (ECSW, contact reduction, greedy loop, RID, partition); batch 1 done: 12 figures in Chapters 1--7; batch 2 done: 8 figures in Chapters 9--12 (map of methods, certified bound, frequency greedy, Craig--Bampton, interface reduction, Loewner, operator inference, nonlinear modal ROMs, backbone); Chapter 14 is next.}
\item \textbf{Chapter~\ref{ch:verif} from the paper.} Verification table against closed forms (patch test, elastica, convergence orders); a summary table of the reproductions (the five of the paper: MFS-NLROM, hybrid ROM, ICE, Loewner/fluid--structure, FD-PINN; and two added from the author's reports: hybrid hyper-reduced contact modelling with its 1D rope and 3D pellet--cladding cases, and assembly reduction with contact and geometric nonlinearity with its 2D case and 3D pipeline; and the FRINO neural-operator study, treated like FD-PINN as a check of the reproduction procedure and not as a method chapter; projection-based reduction for contact problems after Balajewicz et al.; the nonlinear-rods folder is excluded because it has no report) with the paper's outcomes (reproduced, partly, not reproduced); the integrated parametric pipeline with held-out loads, reported by the convention of Appendix~B. The reproduction figures take the paper's as reference but are \emph{regenerated} by a book script (\code{ch14_assets.py}) wherever the study runs in the sandbox; where it cannot, the paper's number is cited as such and not presented as a book result. \emph{Status: done (Chapter~\ref{ch:verif}, \code{ch14_assets.py}, \code{ch14_pipeline.py}).}
\item \textbf{Order of work.} Infrastructure first (algorithm environment, TikZ styles, abbreviations table); a pilot on Chapters~\ref{ch:pod} and~\ref{ch:hyper} for author review; then three batches (Parts~I and~II, Part~III, Chapter~\ref{ch:verif}); rebuild and render-check after each batch. Expected growth: 40 to 50 pages. \emph{Status: infrastructure and pilot done (145 pages, from 137); pilot approved; batches 1 (Chapters 1--7) and 2 (Chapters 9--12) done, 163 pages; batch 3 (Chapter 14) done.}
\end{enumerate}
